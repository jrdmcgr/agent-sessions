# Update sessions pricing

Run from the repo root. `pricing.go` holds USD-per-million-token rates. A model missing from it prices as $0 (`price()` returns nil). The block between `pricing:generated:begin/end` is generated by `bin/update-pricing`; never hand-edit it.

## 1. Find what is unpriced

```sh
sessions --all --json | jq -r '.[] | select(.priced==false) | .models[]' | sort | uniq -c | sort -rn
```

Empty output means nothing is unpriced. Still do step 3 if the ask was to verify rates.

## 2. Add the model and regenerate

1. Add a `ourkey|litellm-key` line to `MODELS` in `bin/update-pricing`. `ourkey` is `claude-<name>` as `sessions` reports it (for example `sessions` shows `opus-5-5`, so use `claude-opus-5-5`). Keep newest first.
2. Run `bin/update-pricing`. It pulls LiteLLM's rate card and rewrites the generated block.
3. Read the output:
   - `kept existing pricing for` is fine: LiteLLM dropped a retired model and the old row stays.
   - `could not find pricing for` means a bad source key. Search the card (`jq -r 'keys[]' | grep <name>`) and fix the `MODELS` line.
4. `go test ./...` and `git diff pricing.go`. Rows should only be added or changed.

## 3. Check against Anthropic

LiteLLM is a third party, so verify new or changed rows against `https://platform.claude.com/docs/en/about-claude/pricing` (WebFetch).

- Compare input, output, 5m cache write and cache read for each changed row. Ignore the 1h cache write column: the table has no field for it.
- Cache-read rates are not always 0.1x input. Read the page's footnotes.
- Report differences to the user as a table. Do not fix by hand-editing the generated block; if LiteLLM is wrong, say so and ask.

## Known limits (deliberate, do not "fix" unasked)

Re-check this list against the pricing page each time; Anthropic may have changed it.

- **Tiered prices are not modelled.** Haiku 5.5 charges 5x for prompts over 100K tokens. The table holds the base tier, so large-context sessions are undercounted. Per-request pricing was judged not worth it for one model.
- **1h cache writes** are priced at the 5m rate (`claude.go` reads only `cache_creation_input_tokens`).
- A model on the pricing page but absent from `MODELS` still shows $0 if used.

## 4. Commit and release

1. Commit `bin/update-pricing` and `pricing.go` separately, one logical change each, with `--only <path>`.
2. Releasing is outward-facing. Run `scripts/release.sh --dry-run patch` (see the header of that script for what it does), show the plan, and run it for real only on the user's go-ahead.
3. After upgrading, re-run step 1 to confirm 0 unpriced.
